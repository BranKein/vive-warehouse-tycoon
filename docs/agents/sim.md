# 서브에이전트 지침: 로직 (sim)

게임 로직 전체를 만든다. 화면 없이 Node에서 돌아가야 한다.

## 고칠 수 있는 곳

- `src/content/` (ID와 섬 배치는 고치지 않는다)
- `src/sim/`
- `src/headless/`
- `tests/sim/`, `tests/content/`, `tests/headless/`

DOM, Three.js, IndexedDB를 import하지 않는다.

## 만들 것

`PLAN.md` 3.3~3.11, 3.15를 구현한다.

1. **내용 데이터** (`src/content`)
   - 메인 에이전트가 초기 데이터를 이미 만들었다: 품목, 레시피, 건물 18종, 업그레이드 트랙, 해금, 입고·판매 수단, 첫 섬의 배치(부지 30칸과 도로 그래프), `catalog`.
   - **ID와 섬 배치는 바꾸지 않는다.** 화면과 UI가 같은 ID와 좌표를 쓴다. 바꿔야 하면 보고에 적는다.
   - 수치(값, 시간, 비용, 성장률, 상한)는 밸런스 목표에 맞춰 자유롭게 조정한다. 지금 값은 첫 추정치다.
   - `catalog`에 없는 밸런스 수치(보관 칸 크기, 폐기물 한계, 무게 감속, 자동 모드 가중치, 특별 화물, 가려진 탭과 무관한 로직 상수)는 `src/content/balance.ts`를 새로 만들어 모은다.
   - 테스트용 두 번째 섬 정의는 `tests/`에 둔다 (게임 내용에는 넣지 않는다)
2. **로직** (`src/sim`)
   - `Game`, `Island`, `IslandManager`
   - `Inventory`, `Recipe`, `ProductionLine`, 건물
   - `Dispatcher`와 `Carrier` (수요 기반 배차, 도로 그래프 경로, 무게에 따른 감속)
   - `InboundChannel`, `SaleChannel`(트럭·배·비행기), `IslandExportChannel`
   - `StatResolver`와 효과 시스템, 폐기물 디버프
   - 업그레이드, 해금, 건설, 철거(들인 돈의 절반 환급)
   - `AutoPilot` (무작위 목표, 부지 예약)
   - 특별 화물
   - 섬을 떠날 때의 수익 추정 (복사본으로 빠르게 돌리기)
   - `contracts`의 `GameSnapshot`을 만들어 내는 부분과 `GameCommands` 구현
   - 저장용 직렬화와 복원 (`contracts`의 `SaveData`)
3. **화면 없는 실행** (`src/headless`)
   - `npm run sim -- --hours <n> [--auto] [--seed <n>]`
   - 출력: 시간별 요약, 첫 2차 건물 해금 시각, 30칸을 채운 시각, 눈에 보이는 변화 사이의 가장 긴 공백
4. **밸런스 1차 조정**
   - 화면 없는 실행으로 `PLAN.md` 4절의 목표에 가깝게 맞춘다. 정밀 조정은 메인이 한다.

## 지켜야 할 것

- 돈과 수량은 모두 `BigNum`이다. `number`로 바꾸는 것은 화면 표시용 계산뿐이다.
- 수와 속도에는 상한을, 양에는 무한 성장을 준다. 상한이 있는 축마다 짝이 되는 무한 축이 있어야 한다.
- 어떤 구매도 초당 수익을 줄여서는 안 된다(철거 제외).
- 난수는 `core`의 시드 난수만 쓴다. `Math.random`을 쓰지 않는다. 같은 시드면 같은 결과가 나와야 한다.
- 한 틱의 계산은 가볍게 유지한다. 4배속과 가려진 탭 따라잡기에서 한 번에 수천 틱을 돌린다.
- 새 생산 라인 종류나 판매 수단을 추가할 때 기존 클래스를 고치지 않아도 되게 한다. 종류 판별 `switch`를 로직 곳곳에 두지 않는다.

## 테스트

- 레시피(입력 여러 개, 출력 여러 개, 폐기물), 배차 우선순위, 판매 시점에만 돈이 들어오는지, 무게 감속, 폐기물 디버프, 철거 환급, 부지 예약, 해금, 직렬화 왕복, 같은 시드의 결정성, 섬 수익 추정이 원래 상태를 바꾸지 않는지
- 오래 돌리는 불변 조건 테스트: 재고와 돈이 음수가 되지 않는다
