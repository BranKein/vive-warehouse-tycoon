# 서브에이전트 지침: UI, 번역, 저장 (ui)

HTML·CSS로 된 게임 UI와 번역, 저장소를 만든다. 프레임워크를 쓰지 않는다.

## 고칠 수 있는 곳

- `src/ui/`
- `src/i18n/`
- `src/save/`
- `tests/ui/`, `tests/i18n/`, `tests/save/`
- `src/ui/dev.html`과 그 진입 파일 (가짜 데이터로 UI만 띄워보는 개발용 페이지)

`src/sim`과 `src/render`를 import하지 않는다. `src/contracts`의 `GameSnapshot`을 읽고 `GameCommands`를 호출한다. 로직이 완성되기 전이므로 `src/contracts/fixtures.ts`의 가짜 데이터로 개발한다.

## 만들 것

### UI (`PLAN.md` 3.14)

- 진입점: `createUI(root, deps)`가 `contracts`의 `GameUI`를 구현한 객체를 돌려준다. `update(snapshot)`이 호출될 때마다 바뀐 부분만 다시 그린다. 매 프레임 DOM 전체를 다시 만들지 않는다.
- 위쪽 띠: 돈, 초당 수익, 속도 버튼(일시정지·1배·2배·4배), 자동 모드, 언어 전환, 저장 메뉴
- 옆 패널
  - 건설: 빈 부지를 고른 뒤 건물 종류 선택. 해금되지 않은 종류는 잠김 표시와 해금 비용
  - 건물 상세: 이름, 레시피(입력 → 출력), 상태(가동 중, 무엇이 모자람, 출고 칸이 참, 폐기물 과다), 업그레이드 트랙별 레벨·효과·비용, 철거(환급액 표시, 한 번 더 확인)
  - 해금 목록
  - 입고·판매 수단·전체 업그레이드
- 저장 메뉴: 수동 저장(개수 제한 없음), 저장 목록에서 불러오기와 지우기, 자동 저장 불러오기, 초기화(한 번 더 확인)
- 알림: 5분 이상 가려져 있다 돌아왔을 때 번 돈, 해금, 특별 화물 보상
- 금액은 `core`의 표기 함수를 쓴다.
- 화면에서 선택(부지, 건물)은 `deps`로 받은 콜백과 `setSelection`으로 화면 쪽과 주고받는다.

### 모양

- 포근하고 몽글몽글한 분위기. 둥근 모서리, 부드러운 그림자, 따뜻한 파스텔 색.
- 3D 화면을 가리지 않게 가장자리에 떠 있는 패널로 둔다. 패널은 접을 수 있다.
- PC 브라우저 기준. 최소 너비 1280px에서 깨지지 않게 한다.
- 색은 CSS 변수로 한곳에 모은다.

### 번역 (`src/i18n`)

- `t(key, params)`와 언어 전환, 전환 알림. 기본 언어는 영어, 고른 언어는 기억한다.
- `en.ts`와 `ko.ts`. 키가 한쪽에만 있으면 타입 오류가 나게 한다.
- 품목·건물·업그레이드·해금의 이름과 설명은 `contracts`의 ID로 키를 만든다 (예: `item.lumber.name`). ID 목록은 `src/contracts/fixtures.ts`와 `PLAN.md`의 품목 표를 본다.

### 저장 (`src/save`, `PLAN.md` 3.12)

- `contracts`의 `SaveStore`를 IndexedDB로 구현한다: 자동 저장 한 칸, 수동 저장 목록(추가·목록·불러오기·삭제), 전체 초기화.
- 저장 데이터의 형식 버전 확인과 단계별 변환 구조(`migrations`). 지금은 버전이 하나뿐이어도 변환 구조와 테스트를 갖춘다.
- 저장 내용 자체(`SaveData`)는 로직이 만든다. 여기서는 내용을 해석하지 않고 보관과 변환만 한다.
- 테스트에서는 메모리 구현으로 바꿔 끼울 수 있게 한다.

## 테스트

- 번역: 키 누락, 매개변수 치환, 언어 전환
- 저장: 메모리 구현으로 추가·목록·불러오기·삭제·초기화, 버전 변환
- UI: 금액 표기와 상태 문구를 만드는 순수 함수
